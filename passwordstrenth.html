    How this works

    What is entropy, and why bits?
    Entropy measures how many guesses a random search would need on average. Each extra bit doubles that number. A password built from a pool of N possible characters at length L has roughly L × log2(N) bits — so both a bigger character pool and more length raise it, but length matters more because it's an exponent.
    Why does the tool ignore some of that entropy for common patterns?
    Raw entropy math assumes every character was chosen randomly. Real passwords aren't — "Password123!" has high raw entropy but is one of the first guesses an attacker's dictionary makes. This tool checks for dictionary words, keyboard runs, and repeated or sequential characters, and marks the password as weak regardless of length when it finds them.
    What does "one-way hash" mean for the reuse check?
    A hash function like SHA-256 turns text into a fixed-length fingerprint that can't be reversed back into the original. This tool hashes a password before storing it, so the history list can spot a repeat without ever keeping the plaintext. Real systems also add a random "salt" per password before hashing, so two identical passwords don't produce identical fingerprints.
